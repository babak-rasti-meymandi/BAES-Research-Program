# BAES Research Program

**Repository:** Public research-program record  
**Program owner:** Babak Rasti Meymandi  
**Status:** Initial structure established; research tracks are not automatically active.

## Purpose

This repository coordinates an independent research program examining engineering, governance, authorization, evidence, and traceability questions arising in Human–AI Engineering Interaction. It provides program-level governance, research planning, methods, source management, and links to bounded research projects.

It is not the BAES standard itself, does not amend BAES, and does not contain confidential BAES material.

## Research posture

The program is evidence-led and must be capable of reaching positive, negative, mixed, or inconclusive findings. It does not presume that BAES is novel, effective, superior, or independently validated.

Every research claim must distinguish:
- **Observation / source statement**
- **Interpretation**
- **Inference**
- **Hypothesis**
- **Unknown / not examined**

Research status must also be explicit: proposed, planned, active, completed, deferred, or closed.

## Repository policy

No new repository is to be created for future BAES-related projects. New work must be placed in an appropriate existing repository, with this repository coordinating cross-project research where appropriate.

Do not copy confidential, licensed, personal, or otherwise restricted material into this public repository. Link to public project records rather than duplicating them. Do not modify another repository merely to keep this index current; cross-repository changes require their own authorization.

## Current starting point

The first proposed research priorities are:
1. Q1 — External framework analysis. NIST AI RMF 1.0 validation is active. The ISO/IEC 42001:2023 workstream is currently Access / Terms Blocked pending verification of a permitted-use route; no substantive preview content has been processed. Q1 remains methodologically distinct from the historical C1–C20 mapping already recorded in the authorization-evaluation repository.
2. Q2 — Academic literature on authority, delegation, control, assurance, and responsibility.
3. Q3 — Empirical research on AI-assisted engineering and authorization/intent-preservation failures.
4. Q6 — Assurance cases and evidence reasoning.
5. Q7 — Systems and software engineering standards relevant to traceability, authority, and accountability.
6. Q5 — Failure modes and mitigations in AI-assisted engineering.
7. Q4 — Publicly researchable terminology questions concerning foundation models.

Priority does not itself authorize a track to begin. See the roadmap and decision register.
